# 组长接口决策

本文记录当前公共层决策，供各模块开发时对齐。

## 命令管理

新增命令统一由组长集中修改 `CommandType`，组员不要在本地随意添加互相冲突的命令名。

本次已增补：

- 学籍：`STUDENT_GET`、`STUDENT_LIST`、`STUDENT_SAVE`
- 选课：`COURSE_LIST_SECTION_STUDENTS`、`COURSE_SAVE_SECTION`、`COURSE_DELETE_SECTION`、`COURSE_SET_ENROLL_PERIOD`
- LMS：`CLASSROOM_CREATE`、`NOTICE_SAVE`、`RESOURCE_UPLOAD`、`RESOURCE_LIST`、`RESOURCE_DELETE`、`ASSIGNMENT_SAVE`、`ASSIGNMENT_LIST_SUBMISSIONS`、`ASSIGNMENT_GRADE`
- 校园BBS：`BBS_LIST_BOARDS`、`BBS_SAVE_BOARD`、`BBS_DELETE_BOARD`、`BBS_LIST_POSTS`、`BBS_GET_POST`、`BBS_SAVE_POST`、`BBS_DELETE_POST`、`BBS_LIST_COMMENTS`、`BBS_SAVE_COMMENT`、`BBS_DELETE_COMMENT`、`BBS_AUDIT_POST`

## 学生表

`student` 表由学籍模块负责维护，其他模块只引用。

固定约定：

- 表名：`student`
- 主键：`student_id`
- 关联账号：`user_id`
- 学号：`student_no`
- 姓名：`name`
- 专业：`major`
- 班级：`class_name`
- 年级：`grade`
- 学籍状态：`status`

学籍模块接口固定为：

- `STUDENT_GET`：按 `studentId` 或 `studentNo` 查询。学生只能查询本人，管理员不限。
- `STUDENT_LIST`：管理员按学号、姓名、专业、班级、状态查询学生列表。
- `STUDENT_SAVE`：管理员新增或修改学生资料，第一版同时用于更新学籍状态。

## 资源上传

第一版采用 `Message.data` 携带 `ResourceUploadRequest`，其中 `content` 字段为 `byte[]`。

约束：

- 单个资源文件最大 5MB
- 服务端收到后保存到项目运行目录下的 `storage/resources/`
- 数据库只保存文件名、大小、类型、存储路径、上传人和上传时间
- `RESOURCE_LIST` 返回 `CourseResourceDTO` 资源元信息，不返回二进制内容
- 下载功能后续如需真传文件，再统一增加 `RESOURCE_DOWNLOAD`

对应公共常量：

```text
SystemConstant.MAX_RESOURCE_UPLOAD_BYTES
```

## 选课和 LMS 表结构

选课系统表由课程负责人维护，第一版表名固定为：

- `course`
- `course_section`
- `enrollment`

在线课堂表由 LMS 负责人维护，第一版表名固定为：

- `classroom`
- `notice`
- `course_resource`
- `assignment`
- `assignment_submission`

模块 SQL 先放在：

```text
sql/modules/course_classroom_schema.sql
```

最终合并时必须保证 `student`、`sys_user`、`course` 等被依赖表先创建。

## 请求分发

`RequestDispatcher` 已改为 `Map<CommandType, RequestHandler>` 注册表结构。各模块后续只注册自己的 handler，不再堆大量 `if-else`。

## 鉴权

`RequestDispatcher` 统一做 token 和角色检查。

- `SYSTEM_PING`、`USER_LOGIN` 不需要 token
- 其他注册命令默认需要登录
- 管理员、教师、学生权限在 `CommandPolicy` 中集中维护

服务端不要相信客户端传来的角色，应以 token 对应的服务端 session 为准。

## 事务

涉及多条 SQL 必须原子化的业务，使用 `TransactionManager` 在 service 层开启事务。DAO 方法如果参与事务，应接收同一个 `Connection`。

选课模块的“容量条件更新 + 写入选课记录”必须放在同一个事务中。

## 密码

`temporary-test-password` 只用于初期联调。正式版本需要替换为密码散列。
