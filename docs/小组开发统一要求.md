# vCampus 小组开发统一要求

各位同学，项目基础骨架已经完成，并已通过 Maven 编译、Socket 通信、MySQL 连接和登录闭环验证。接下来可以开始各业务模块开发。

为了避免后期合并冲突、接口不一致、数据库外键对不上，后续开发统一按下面规则执行。

## 一、红黄绿决策规则

### 绿色事项：模块负责人自己决定

这些属于模块内部实现，不需要每次问组长：

- 界面布局、按钮文字、表格列展示顺序
- 模块内部类名、方法名、工具方法
- DAO 内部 SQL 写法
- 不影响其他模块的实现细节

### 黄色事项：先在群里同步，默认可做

这些内容可能影响别人理解，但通常不需要逐条拍板：

- 新增自己模块的 DTO
- 新增自己模块的 Service、DAO
- 新增自己模块的数据表
- 新增自己模块的客户端界面

要求：先在群里发设计草案。如果没有人提出冲突，就可以继续写。

### 红色事项：必须统一确认后再改

这些会影响全组，不能私自修改：

- `Message`
- `CommandType`
- `ResponseCode`
- `sys_user` 表
- `student` 表
- 跨模块外键
- 其他模块已经依赖的数据表字段
- 登录逻辑、token 鉴权、角色权限
- 事务规则
- Maven 父工程依赖

## 二、模块代码位置

每个模块都按下面结构放代码。

```text
vcampus-common  放 DTO、enum、公共协议、公共异常、公共常量
vcampus-client  放 view、client service、network、session
vcampus-server  放 server service、dao、network、database、security
```

例如课程模块：

```text
vcampus-common/src/main/java/edu/seu/vcampus/common/dto/course/
vcampus-client/src/main/java/edu/seu/vcampus/client/view/course/
vcampus-client/src/main/java/edu/seu/vcampus/client/service/course/
vcampus-server/src/main/java/edu/seu/vcampus/server/service/course/
vcampus-server/src/main/java/edu/seu/vcampus/server/dao/course/
```

## 三、开发顺序

每个模块建议按这个顺序开发：

```text
1. 先定 DTO
2. 再定 CommandType
3. 写 server service
4. 写 dao
5. 写 client service
6. 最后写 Swing view
```

先把数据链路跑通，再做界面。

## 五、CommandType 规则

命令统一使用：

```text
模块名_动作
```

例如：

```text
USER_LOGIN
COURSE_LIST
COURSE_ENROLL
BOOK_SEARCH
RESOURCE_UPLOAD
ASSIGNMENT_GRADE
```

新增 `CommandType` 前必须先在群里同步，避免重复命名。

## 六、数据库规则

登录账号统一使用：

```text
sys_user
```

学生信息统一使用：

```text
student
```

字段统一为：

```text
student_id   学生主键
user_id      关联 sys_user(user_id)
student_no   学号
name         姓名
major        专业
class_name   班级
grade        年级
status       学籍状态
```

选课、作业提交等模块需要引用学生时，统一引用：

```text
student(student_id)
```

各模块 SQL 可以先放到：

```text
sql/modules/
```

最终由组长统一合并到总 SQL，并按外键依赖排序。

## 七、资源上传规则

课程资源上传第一版统一采用：

```text
客户端读取文件为 byte[]
放进 Message.data
服务端接收后保存到 storage/resources/
数据库保存文件元信息和路径
```

单个资源文件暂定限制：

```text
5MB 以内
```

代码里统一使用：

```text
SystemConstant.MAX_RESOURCE_UPLOAD_BYTES
```

资源表统一叫：

```text
course_resource
```

如果后续要做真正下载功能，再统一增加：

```text
RESOURCE_DOWNLOAD
```

第一版 `RESOURCE_LIST` 只返回 `CourseResourceDTO` 资源元信息，不返回文件二进制内容。

## 八、权限规则

当前统一规则：

```text
SYSTEM_PING 不需要登录
USER_LOGIN 不需要登录
其他功能默认需要 token
```

角色分为：

```text
ADMIN
TEACHER
STUDENT
```

模块管理员不新增为基础角色，统一通过 `sys_module_admin` 授权。系统管理员负责授权，模块负责人进入自己模块后再显示管理功能。

权限判断统一在服务端做，各模块不要自己单独写一套鉴权逻辑。

## 九、事务规则

涉及多条 SQL 且必须一起成功的操作，一定要使用事务。

例如选课：

```text
1. 判断课程容量
2. 更新已选人数
3. 插入选课记录
```

这三步必须要么全部成功，要么全部失败。

项目里已经提供：

```text
TransactionManager
```

后续这类操作优先用它。

## 十、Git 提交规则

提交前不要包含：

```text
db.properties
target/
build/
.settings/
.project
.classpath
*.class
*.jar
*.log
```

`db.properties` 是每个人自己的本机数据库密码配置，不能上传 GitHub。

## 十一、当前优先级

大家现在优先做：

```text
1. 明确自己模块的 DTO
2. 明确自己模块的 CommandType
3. 明确自己模块的数据表
4. 先跑通 service + dao
5. 最后再补 Swing 界面
```

请各模块负责人先按“接口申请格式”发一版草案到群里，对齐后再正式开发。

## 十二、当前已确认模块补充

### 学籍模块

学籍模块负责维护 `student` 表。其他模块只引用 `student(student_id)`，不重复建学生表。

接口固定为：

```text
STUDENT_GET   按 studentId 或 studentNo 查询；学生只能查本人，管理员不限
STUDENT_LIST  管理员按学号、姓名、专业、班级、状态查询学生列表
STUDENT_SAVE  管理员新增或修改学生资料；第一版同时用于更新学籍状态
```

学籍模块请求对象统一使用：

```text
StudentGetRequest(studentId, studentNo)
StudentQuery(studentNo, name, major, className, status, pageNo, pageSize)
```

### 选课系统

选课模块第一版负责：

```text
1. 学生浏览可选课程/开课班
2. 学生选课、退课
3. 学生、教师查看课表
4. 教师查看开课班名单
5. 管理员增改删开课班、配置选课期
```

选课时间冲突统一使用：

```text
week_day
start_period
end_period
```

### LMS 在线课堂

LMS 第一版负责：

```text
1. 教师创建课堂
2. 公告发布与列表
3. 课程资源上传/列表/删除
4. 教师布置作业、学生提交、教师批改评分
```

课程资源第一版采用 `byte[]` 上传，数据库保存 `storage_path`，下载功能后续统一评估。
