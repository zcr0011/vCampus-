# vCampus 模块接口基线

本文档说明当前已经冻结的模块接口骨架。组员开发时优先按照这里的目录和接口补代码，不要另起一套命名。

## 一、整体原则

客户端界面只调用 `client.service`，不直接操作 Socket，不直接访问数据库。

服务端业务写在 `server.service`，数据库访问写在 `server.dao`。涉及多条 SQL 必须一起成功的操作，在 service 层使用 `TransactionManager`。

所有网络传输对象放在 `vcampus-common/src/main/java/edu/seu/vcampus/common/dto`，并实现 `Serializable`。

## 二、通用 DTO

通用请求对象位于：

```text
vcampus-common/src/main/java/edu/seu/vcampus/common/dto/common
```

已提供：

```text
IdRequest              单个 id 请求
PageQuery              分页/关键词查询
PageResult             分页结果
StatusChangeRequest    状态修改请求
```

分页列表统一优先返回：

```text
PageResult<T>: total, list
```

为兼容早期代码，`PageResult` 也保留 `rows()` 方法，但新模块统一使用 `list()`。

## 三、模块目录

每个模块都按照相同层级存放：

```text
vcampus-common/src/main/java/edu/seu/vcampus/common/dto/模块名
vcampus-client/src/main/java/edu/seu/vcampus/client/service/模块名
vcampus-client/src/main/java/edu/seu/vcampus/client/service/模块名/impl
vcampus-client/src/main/java/edu/seu/vcampus/client/view/模块名
vcampus-server/src/main/java/edu/seu/vcampus/server/service/模块名
vcampus-server/src/main/java/edu/seu/vcampus/server/dao/模块名
```



公共 DTO：

```text

```

## 五、当前后端状态

`RequestDispatcher` 已经为全部 `CommandType` 注册了占位处理器。除 `SYSTEM_PING`、`USER_LOGIN`、`USER_LOGOUT` 外，其余模块命令当前会返回：

```text
NOT_IMPLEMENTED
```

这表示接口已经固定，但具体业务还没有写。模块负责人后续实现 service 后，再把对应命令从占位处理器替换为真实 handler。

## 六、界面同学怎么用

界面层拿到 `ClientConnection` 后，创建对应模块的 ClientService。

示例：

```java
BbsClientService bbsService = new BbsClientServiceImpl(connection);
Message response = bbsService.listPosts(new PageQuery("", 1, 20));
```

界面只处理输入、按钮、表格、提示框。真正的网络请求已经由 ClientService 封装。

## 七、模块负责人后续要补什么

每个模块负责人至少补完：

```text
1. DTO 字段是否够用，不够先在群里同步
2. sql/modules/模块名_schema.sql
3. DAO 实现类
4. ServerService 实现类
5. RequestDispatcher 中把占位 handler 替换成真实 handler
6. 模块最小闭环测试
```

公共层、跨模块外键、权限和事务规则仍按《小组开发统一要求》执行。
