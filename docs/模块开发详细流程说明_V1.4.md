# vCampus 模块开发详细流程说明 V1.4

本文档给各模块负责人使用。目标是让每个同学按照统一结构开发自己的模块，最后组长合并时不需要大改框架。

当前图书馆模块已经作为示范完成一版较完整实现，其他模块建议参考图书馆模块的目录、接口、权限、界面和测试方式。

## 一、开发总原则

每个模块都要遵守以下规则：

```text
1. 客户端界面只写 Swing 页面，不直接访问数据库。
2. 客户端页面只能调用 client service。
3. client service 通过 Message + CommandType 调用服务端。
4. 服务端 Handler 只负责接收 Message、取 requestId、取 currentUser、调用 Service、包装 Message.success。
5. 服务端 Service 负责业务规则、权限细节和事务边界。
6. 服务端 DAO 负责 SQL 和数据库字段映射。
7. 公共 DTO 放在 vcampus-common。
8. 所有模块页面都接入 MainFrame，不单独创建 JFrame。
9. 慢操作使用 SwingWorker，不能卡住界面。
10. 危险操作必须二次确认，例如删除、冻结、下架、取消授权。
11. 操作失败时显示服务端返回的错误信息。
```

## 二、标准目录结构

每个模块建议按下面结构放代码。

以图书馆模块为例：

```text
vcampus-common
  src/main/java/edu/seu/vcampus/common/dto/book
    BookDTO.java
    BookQueryDTO.java
    BookLoanDTO.java
    BookLoanQueryDTO.java
    BookLoanViewDTO.java
    LibraryStatsDTO.java

vcampus-client
  src/main/java/edu/seu/vcampus/client/service/book
    BookClientService.java
  src/main/java/edu/seu/vcampus/client/service/book/impl
    BookClientServiceImpl.java
  src/main/java/edu/seu/vcampus/client/view/book
    LibraryPanel.java

vcampus-server
  src/main/java/edu/seu/vcampus/server/dao/book
    BookDAO.java
  src/main/java/edu/seu/vcampus/server/dao/book/impl
    BookDAOImpl.java
  src/main/java/edu/seu/vcampus/server/service/book
    BookServerService.java
  src/main/java/edu/seu/vcampus/server/service/book/impl
    BookServerServiceImpl.java
  src/main/java/edu/seu/vcampus/server/service/book
    BookModuleHandler.java

sql/modules
  xxx_schema.sql

docs
  xxx模块说明.md
```

其他模块只需要把 `book` 换成自己的模块名，例如：

```text
student
course
shop
bank
dorm
classroom
bbs
```

服务端最终标准是三层分离：

```text
ModuleHandler -> ServerServiceImpl -> DAOImpl
```

`ModuleHandler` 不直接写 SQL。早期某些模块如果还把 SQL 写在 Handler 里，视为临时骨架，后续都要拆到 DAOImpl。

## 三、开发一个模块的完整流程

### 第一步：先确定模块功能

每个模块先写清楚三类功能：

```text
普通学生能做什么
普通教师能做什么
模块管理员能做什么
```

例如图书馆：

```text
普通读者：
图书检索、借阅、查看我的借阅、归还、续借

图书管理员：
新增图书、编辑图书、上架/下架、查看全体借阅记录
```

### 第二步：确定 CommandType

每个前后端交互动作都要有一个命令。

命名规则：

```text
模块名_动作
```

示例：

```text
BOOK_SEARCH
BOOK_STATS
BOOK_BORROW
BOOK_RETURN
BOOK_RENEW
BOOK_LIST_LOANS
BOOK_SAVE
BOOK_UPDATE_STATUS
BOOK_DELETE
```

新增命令统一写到：

```text
vcampus-common/src/main/java/edu/seu/vcampus/common/protocol/CommandType.java
```

注意：新增命令后，服务端必须在对应模块 handler 里注册，否则客户端发过去会提示“不支持该命令”。

### 第三步：设计 DTO

DTO 是客户端和服务端传输的数据对象，放在 `vcampus-common`。

建议每个模块至少准备：

```text
基础信息 DTO
查询条件 DTO
列表展示 DTO
保存请求 DTO
状态修改请求 DTO，如果公共 StatusChangeRequest 能满足就复用公共类
```

例如图书馆：

```text
BookDTO              图书基础信息
BookQueryDTO         图书检索条件
BookLoanDTO          借阅记录基础信息
BookLoanQueryDTO     借阅记录查询条件
BookLoanViewDTO      借阅监管展示信息
LibraryStatsDTO      图书馆首页统计
```

DTO 要实现 `Serializable`，因为当前网络层使用 Object 序列化传输。

推荐写法：

```java
public record BookQueryDTO(String keyword, String status, Boolean onlyAvailable,
        Integer pageNo, Integer pageSize) implements Serializable {

    private static final long serialVersionUID = 1L;
}
```

### 第四步：写客户端 service

客户端 service 的职责是把页面请求封装成 Message。

接口放在：

```text
vcampus-client/src/main/java/edu/seu/vcampus/client/service/模块名
```

实现放在：

```text
vcampus-client/src/main/java/edu/seu/vcampus/client/service/模块名/impl
```

示例：

```java
public interface BookClientService {
    Message search(BookQueryDTO query);
    Message borrow(IdRequest bookId);
}
```

实现示例：

```java
public Message search(BookQueryDTO query) {
    return send(CommandType.BOOK_SEARCH, query);
}
```

页面不要直接创建 Message，页面只调用自己的 `XxxClientService`。

### 第五步：写服务端 handler

服务端 handler 负责接收命令、校验参数、调用数据库、返回 Message。

位置：

```text
vcampus-server/src/main/java/edu/seu/vcampus/server/service/模块名
```

每个模块 handler 必须提供：

```java
public void register(Map<CommandType, RequestHandler> handlers) {
    handlers.put(CommandType.XXX_XXX, wrap(this::method));
}
```

例如：

```java
handlers.put(CommandType.BOOK_SEARCH, wrap(this::search));
handlers.put(CommandType.BOOK_BORROW, wrap(this::borrow));
```

返回成功时使用：

```java
return ok(request, data);
```

业务错误使用：

```java
throw new BusinessException(ResponseCode.VALIDATION_ERROR, "提示信息");
throw new BusinessException(ResponseCode.CONFLICT, "提示信息");
throw new BusinessException(ResponseCode.FORBIDDEN, "提示信息");
```

### 第六步：在 RequestDispatcher 注册模块

如果是新模块，需要在：

```text
vcampus-server/src/main/java/edu/seu/vcampus/server/network/RequestDispatcher.java
```

中注册：

```java
new XxxModuleHandler().register(handlers);
```

如果模块管理员可以执行某些管理命令，也要在 `moduleAdminCode()` 中登记。

示例：

```java
case BOOK_SAVE, BOOK_UPDATE_STATUS, BOOK_DELETE -> "BOOK";
```

含义：拥有 `BOOK` 模块权限的用户，可以执行这些图书馆管理命令。

### 第七步：配置权限规则

权限统一写在：

```text
vcampus-server/src/main/java/edu/seu/vcampus/server/security/CommandPolicy.java
```

例如：

```java
allow(CommandType.BOOK_SEARCH, RoleType.ADMIN, RoleType.TEACHER, RoleType.STUDENT);
allow(CommandType.BOOK_SAVE, RoleType.ADMIN);
```

说明：

```text
普通命令：按基础角色开放
管理命令：默认给 ADMIN，然后由 RequestDispatcher 放行对应模块管理员
```

不要新增 `BOOK_ADMIN`、`SHOP_ADMIN` 这种基础角色。模块管理员通过 `sys_module_admin` 授权。

### 第八步：设计数据库表

模块自己的 SQL 放到：

```text
sql/modules/模块名_schema.sql
```

SQL 要写清楚：

```text
表名
主键
外键
唯一约束
状态字段
演示数据
```

如果依赖其他模块，必须明确写出来。例如图书馆依赖：

```text
book_loan.user_id -> sys_user.user_id
```

如果涉及跨模块事务，例如商店支付调用银行扣款，必须提前和组长确认事务边界。

### 第九步：写 Swing 页面

所有模块页面都必须是：

```java
public class XxxPanel extends JPanel
```

不要自己创建 `JFrame`。

统一由 `MainFrame` 切换：

```text
MainFrame -> XxxPanel
```

模块页面建议分两层：

```text
模块首页：
展示模块概要信息 + 子功能入口

子功能页：
具体查询、表格、表单、操作按钮
```

### 第十步：接入 MainFrame

在：

```text
vcampus-client/src/main/java/edu/seu/vcampus/client/view/MainFrame.java
```

中把模块入口接进去。

如果模块尚未完成，可以先使用占位页：

```java
return new BusinessModulePanel(...);
```

如果模块已经完成自己的页面，就接：

```java
return new XxxPanel(connection, currentUser, () -> showPage(WORKBENCH_PAGE));
```

### 第十一步：测试模块

每个模块至少测试：

```text
1. Maven test 或 javac 编译通过
2. 服务端可以启动
3. 客户端可以登录
4. 普通学生账号能访问自己应该看到的功能
5. 普通教师账号能访问自己应该看到的功能
6. 没权限的人看不到管理功能
7. 模块管理员能看到管理功能
8. 错误操作有提示，不会让程序崩溃
```

图书馆测试示例：

```text
学生登录 -> 图书馆 -> 图书检索 -> 借阅
学生登录 -> 图书馆 -> 我的借阅 -> 续借/归还
系统管理员登录 -> 用户管理 -> 授权某用户 BOOK 模块权限
被授权用户重新登录 -> 图书馆 -> 馆藏维护/借阅监管
```

## 四、GUI 统一要求

客户端已经提供共享样式类：

```text
edu.seu.vcampus.client.view.component.CampusUI
```

推荐使用：

```java
CampusUI.primaryButton("检索");
CampusUI.secondaryButton("返回");
CampusUI.neutralButton("刷新");
CampusUI.dangerButton("删除");
CampusUI.cardBorder();
CampusUI.styleTable(table);
```

按钮含义：

```text
蓝色主按钮：检索、新增、提交、确认、借阅
白底蓝字按钮：返回、编辑、续借
白底普通按钮：刷新、清空
红色按钮：删除、冻结、下架、取消授权
```

页面颜色统一参考：

```text
背景色：#F5F7FB
主蓝色：#2F65E7
文字主色：#0F172A
辅助文字：#64748B
边框：#E2E8F0
```

禁止：

```text
1. 不要使用 null 布局。
2. 不要使用绝对坐标。
3. 不要让界面直接访问数据库。
4. 不要单独创建 JFrame。
5. 不要把网络请求写在按钮事件里阻塞界面线程。
```

## 五、参考图书馆模块的页面设计

图书馆现在提供了两类页面示范。

### 1. 检索类页面

适合：

```text
图书检索
商品浏览
课程浏览
BBS 帖子列表
在线课堂资源列表
```

结构：

```text
顶部大搜索框
左侧筛选栏
中间结果卡片
右侧选中详情
```

### 2. 管理类页面

适合：

```text
用户管理
馆藏维护

```

结构：

```text
顶部查询工具栏
中间表格
右侧详情栏或弹窗表单
底部/工具栏操作按钮
```

## 六、提交给组长前的检查清单

每个模块提交前请确认：

```text
1. CommandType 已列清楚。
2. DTO 都放在 common。
3. client service 不直接访问数据库。
4. Swing 页面只调用 client service。
5. server handler 已注册命令。
6. CommandPolicy 权限已声明。
7. 模块管理员命令已在 RequestDispatcher.moduleAdminCode() 登记。
8. SQL 文件已提交。
9. 页面能返回模块首页或工作台。
10. 编译通过。
11. 至少用一个学生账号、一个教师账号、一个模块管理员账号测试过。
```

## 七、模块负责人交付格式

每个模块负责人交付时，建议发给组长：

```text
【模块名称】

【实现功能】

【新增 CommandType】

【新增 DTO】

【新增或修改的数据表】

【客户端页面入口】

【服务端 Handler】

【权限说明】

【测试账号和测试步骤】

【仍需组长协调的问题】
```

这样合并时能快速判断是否会影响公共层和其他模块。
